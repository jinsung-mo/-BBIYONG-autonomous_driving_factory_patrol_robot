본 문서는 팀 E101의 원활한 협업과 체계적인 일정 관리를 위한 Jira(지라) 티켓 및 Git 연동 컨벤션 규칙을 정의합니다. 모든 팀원은 작업 시작 전 본 규칙을 숙지하고 일치된 컨벤션을 준수합니다.

## 1. Jira 티켓 제목(Summary) 규칙

티켓 제목은 한눈에 작업 성격을 파악할 수 있도록 **`[접두사] 작업 내용 요약`** 형식으로 간결하게 작성합니다.

### 1.1 주요 접두사(Prefix) 정의
* **`[Feat]`** or **`[Feature]`**: 새로운 기능 구현 및 개발
  * *예시*: `[Feat] 웹 관제 화면의 WASD 소켓 제어 컨트롤러 개발`
* **`[Fix]`** or **`[Bug]`**: 오동작 수정 및 버그 픽스
  * *예시*: `[Fix] 로봇 TCP 소켓 연결 순단 시 재연결 실패 예외 수정`
* **`[Docs]`**: 문서 작성 및 수정 (기획서, 명세서, README 등)
  * *예시*: `[Docs] 백엔드 - 로봇 간 TCP 소켓 통신 API 명세 보완`
* **`[Design]`**: UI/UX 디자인 및 화면 퍼블리싱 작업
  * *예시*: `[Design] 관제 웹 대시보드 실시간 지도 컴포넌트 마크업`
* **`[Refactor]`**: 코드 가독성 개선, 성능 최적화 등 구조 개선 (기능 변화 없음)
  * *예시*: `[Refactor] 소켓 통신 핸들러 비동기 스레드 풀 적용`
* **`[Chore]`**: 의존성 라이브러리 추가, 빌드 설정 및 단순 인프라 설정 수정
  * *예시*: `[Chore] SQLite JPA 라이브러리 추가 및 기본 DB 접속 파일 구성`
* **`[Test]`**: 테스트 코드 작성 및 기능 검증 작업
  * *예시*: `[Test] REST API 예외 핸들러 단위 테스트 작성`

## 2. Jira 티켓 본문(Description) 작성 템플릿

작업 상세 내역과 완료 기준을 투명하게 공유하기 위해, 티켓 생성 시 아래 **3단계 템플릿**을 복사하여 작성합니다.

```markdown
### 📋 개요 (Context)
- (이 작업을 진행하게 된 배경이나 목적을 1~2줄로 서술합니다.)
- 예: CCTV 1차 화재 감지 후 로봇을 즉시 현장으로 급파하기 위한 핵심 로직을 백엔드에 반영합니다.

### 🛠️ 작업 상세 내용 (To-Do)
- [ ] CCTV 화재 수신용 REST API 컨트롤러 구현
- [ ] 수신 시 로봇 FSM 상태를 DISPATCH로 전환하는 비즈니스 로직 작성
- [ ] 로봇 TCP 소켓을 통해 출동 명령 패킷 전송 로직 연동

### ✅ 완료 기준 (Definition of Done)
- [ ] CCTV 화재 수신 API 호출 시 로봇 FSM이 정상적으로 전이되는지 로그 확인
- [ ] API 호출 결과 포스트맨 문서 테스트 통과 완료
```

## 3. Git ↔ Jira 연동 규칙 (강력 권장)

Jira 프로젝트와 GitLab/GitHub을 연동하여 작업 이력을 완벽하게 추적(Traceability)하기 위한 커밋 및 브랜치 명명법입니다.

### 3.1 브랜치명 컨벤션
* 형식을 지켜 작성하면 Jira 티켓 우측 하단에 브랜치 생성 정보가 자동으로 링크됩니다.
* **형식**: `[접두사]/[Jira티켓번호]-[간단한작업명]`
* **예시**: 
  * `feat/S15P11E101-125-socket-server`
  * `fix/S15P11E101-38-reconnect-bug`

### 3.2 커밋 메시지 컨벤션
* 커밋 메시지 맨 앞에 대괄호로 **Jira 티켓 번호**를 적어주면 해당 커밋 로그가 지라 티켓에 자동으로 기록됩니다.
* **형식**: `[Jira티켓번호] 접두사: 커밋 메시지`
* **예시**:
  * `[S15P11E101-125] feat: Spring Boot 직접 TCP 소켓 서버 구현`
  * `[S15P11E101-38] fix: 로봇 소켓 연결 해제 시 재연결 실패 핸들러 수정`
