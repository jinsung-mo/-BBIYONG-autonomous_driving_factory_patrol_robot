## 1. 제품 전제

- **삐용은 20시~08시, 공장이 빈 시간에만 돈다.** 관제 화면은 벽에 띄워 두고 보는 물건이지,
  사람이 계속 붙어 조작하는 화면이 아니다.
- **화면이 죽으면 안전 장치가 죽는다.** 로그아웃되면 긴급 정지 버튼조차 누를 수 없다.
  디자인 결정이 이 사실을 이기면 안 된다.
- 영상·열화상·지도는 **판독 대상**이다. 장식이 그것을 흐리면 목적이 뒤집힌다.
- 편성된 순찰 로봇은 **오린카-01(`orinka_01`) 1대**다. 화면의 '제어 대상'은 항상 이 로봇이고,
  편성 목록에서 고르는 것은 **조회 대상**이지 제어 대상이 아니다.

## 2. 기술 스택과 파일 구조

React 18.3 + Vite 5 + TypeScript(`strict: true`). **CSS 프레임워크를 쓰지 않는다** —
Tailwind·Bootstrap 등을 넣지 않았고, 검증에서 프레임워크 흔적 0 · 외부 스타일시트 0을 확인한다.

## 3. 앱 구조 — 진입 · 컨텍스트 · 탭

### 진입 흐름

```
WelcomeScreen  →  AuthScreen(로그인/회원가입)  →  Dashboard
   랜딩              자동 로그아웃 시 여기로 직행
```

`Gate` 가 판단한다. 로그인 상태면 `SessionWatcher` + `Dashboard`, 아니면 랜딩/로그인.

### 컨텍스트 계층

```
AuthProvider                 세션 · 권한 · 조작 잠금
└─ SimContext.Provider       시뮬레이션 상태 스냅샷 · 캔버스 ref · 액션
   └─ SettingsProvider       속도 상한 · 임계 온도 · 순찰 지점
      └─ LiveProvider        STOMP · 경보 · 텔레메트리 · 제어 발행
         └─ FleetProvider    대시보드 집계(30초) — SummaryBar/FleetList 공유
            ├─ LiveSimBridge   실서버 프레임을 캔버스로
            ├─ EventLogActivity 이벤트 기록을 활동으로
            ├─ Nav
            ├─ EventAlert      경보 토스트 · 화재 점멸 (탭 무관, 항상)
            └─ RobotPage / OpsPage / ConfigPage
```

**관제 화면은 계속 마운트해 둔다**(`hidden` 속성으로 감춤). 탭을 옮겼다고 캔버스와 STOMP
구독을 버리면 돌아올 때마다 맵과 영상이 처음부터 다시 붙는다.

### 탭

| 탭 | 권한 | 내용 |
| --- | --- | --- |
| **관제** | 전원 | 로봇 상태 · 전면 카메라 · 열화상 · 2D 지도 · 수동 조작 · 이벤트 로그 |
| **운영** | 관리자 | 맵 모델링 · 저장된 맵 · 순찰 경로 · 스케줄 · 건강 이력 · 이벤트 통계 |
| **설정** | 관리자 | 주행 상한 · 임계 온도 · 순찰 지점 · 설비 임계 · 알림 · 사용자 관리 · 시연 경보 |

권한이 줄어들면(관리자 → 사용자 재로그인) 접근 가능한 탭으로 되돌린다.

### 두 가지 데이터 원천

| | **시뮬레이션(mock)** | **실서버(live)** |
| --- | --- | --- |
| 전환 | 상단 바 토글 · `localStorage['bbiyong.dataSource']` | 같음 |
| 영상 | `Simulation.ts` 가 캔버스에 직접 그림 | STOMP `/topic/video/{robot}` 프레임 |
| 상태 | 시뮬 상태 기계 | STOMP `/topic/robots` 텔레메트리 |
| 인증 | `localStorage` 목 저장소 | REST `/api/auth/*` + JWT |
| 조작 | 시뮬 상태를 바꿈 | STOMP 제어 발행 → 로봇 |
| 기본값 | **mock** — 설정 없이 받은 사람의 데모가 바뀌지 않게 | |

│ 순찰 로봇     │  순찰 로봇 카메라        │ 순찰 로봇 열화상 카메라 │

CSS 그리드 — 좌측 상태 열은 고정 폭, 가운데와 우측이 남는 폭을 나눈다.

```css
.b-grid{
  grid-template-columns: 290px 1.15fr 1fr;
  grid-template-rows: 1.7fr 1fr;
  grid-template-areas: "status cam right"
                       "status control right";
}
```

시뮬 스킨에서는 `minmax()` 로 감싸고 간격을 `clamp(10px,1.45vh,16px)` 로 준다 —
낮은 창에서 먼저 좁아지되 무너지지 않게.

### 카메라 확대 (`#pgB.cam-full`) — 별도 티켓 대기

> 아래는 구현·검증을 마쳤으나 **아직 병합되지 않았다**(별도 티켓 대기).
> `fe/dev` 에는 없다. 이 절은 그 기능이 들어올 때의 설계를 미리 적어 둔 것이다.

전면 카메라를 **더블클릭**하면 상단 바 아래 전체를 채우고, **열화상이 우측 아래에 함께** 뜬다.
화재를 의심할 때 전면 영상만 크게 봐서는 판단이 반쪽이다 — 불꽃이 보이는 자리와 열이
오르는 자리를 같이 봐야 한다.

- 어두운 막을 깔지 않는다. **배경은 그대로 두고 영상만 크게** 띄운다.
- 상단 바 아래에서 시작한다. 반쯤 덮으면 가린 것도 보인 것도 아닌 모양이 된다.
- 열화상 PiP 는 **영상 자체가 창**이다 — 여백 없이 영상이 채우고 이름표는 위에 칩으로.
- DOM 을 옮기지 않고 CSS 로 자리만 바꾼다. 캔버스는 매 프레임 부모 크기에 맞춰지므로
  (`Simulation.fit`) 크기가 따라오고 프레임 수신이 끊기지 않는다.

### 운영 탭 · 설정 탭

`.cfg-grid` — `repeat(auto-fit, minmax(330px,1fr))` 카드 나열. 차트는 폭이 좁으면 읽기
어려워 `.ops-grid` 로 2열까지만 벌린다.

| 운영 탭 | 설정 탭 |
| --- | --- |
| 2D 맵 모델링 · 저장된 맵 | 주행 속도 상한 · 열화상 임계 온도 |
| 순찰 경로(지도 위 편집) | 순찰 지점 · 초기화 |
| 자동 순찰 스케줄 | 설비별 과열 임계 온도 |
| 로봇 건강 이력 · 이벤트 통계 | Mattermost 알림 · 사용자 관리 · 시연 경보 |

## 5. 디자인 톤

### 색 토큰

두 벌을 둔다. `--*` 는 라이트 설계(CCTV 계열), `--dk-*` 는 다크 설계(로봇 관제 계열)이고,
테마 전환 시 서로를 덮어써 전체가 한 톤으로 맞는다.

```css
:root{
  --ink:#1c2128; --sub:#68727f; --line:#e3e7ee; --bg:#f2f4f8; --card:#fff;
  --red:#e2483d; --blue:#2f6fd0; --green:#1f9d6c;
  --dk-bg:#0b0d11; --dk-panel:#14171d; --dk-panel2:#1a1e26; --dk-line:#262b34;
  --dk-ink:#e6e9ef; --dk-sub:#8b93a3;
  --dk-green:#3ddc97; --dk-amber:#f5a623; --dk-red:#ff5648;
}
:root[data-theme="dark"] { --ink → 밝게, --bg → 어둡게 … }
:root[data-theme="light"]{ --dk-bg → 밝게, --dk-panel → 흰색 … }
```

### 의미 색

| 색 | 의미 | 쓰이는 곳 |
| --- | --- | --- |
| 초록 `--dk-green` | 정상 · 진행 중 | 순찰 중 · E-STOP 해제 · 통신 양호 · 순찰 복귀 |
| 호박 `--dk-amber` | 주의 · 대기 | 과열 · 수동 모드 · 로봇 오프라인 · 미해결 |
| 빨강 `--dk-red` | 위험 · 되돌릴 수 없음 | 화재 · E-STOP 체결 · 긴급 정지 · 삭제 |
| 파랑 `#2f6fd0` 계열 | 선택 · 활성 | 선택된 탭 · 순찰 모드 · 방향 패드 눌림 |

### 타이포

- 본문 `'Malgun Gothic', system-ui` 13px 기준.
- **수치는 `Consolas` 등폭 + `font-variant-numeric: tabular-nums`.**
  값이 바뀔 때 자릿수가 흔들리면 읽는 사람이 다시 읽어야 한다.
- 패널 제목은 작고 조용하게(10.5px, letter-spacing 1.4px), 영문 키(`FRONT · YOLOv11n`)를
  칩으로 분리해 붙인다.

### 형태

| | 기본 화면 | 시뮬 스킨 |
| --- | --- | --- |
| 패널 반지름 | 12px | `--r: 26px` |
| 패널 여백 | 13px | `--pad: 14px` |
| 안쪽 상자 | 8~14px 제각각 | `--r-in: 12px` = `--r` − `--pad` (동심원) |
| 알약 | 9px | `999px` (버튼·세그먼트·게이지) |

**동심원 규칙** — 안쪽 반지름 = 바깥 − 여백. 값을 따로 적지 않고 계산으로 묶는다.
어긋나면 두 곡선이 평행하지 않아 눈에 거슬린다.

### 시뮬 스킨의 재질

`--blur: 30px` · `--sat: 1.9` (판별 최대 2.3). 자세한 것은 [8절](#8-liquid-glass--넣은-것과-뺀-것).

## 6. 버튼과 조작 전부

### 관제 — 수동 조작 패널

| 조작 | 단축키 | 잠금 | 동작 |
| --- | --- | --- | --- |
| **■ 긴급 정지** | `Shift`(해제 상태에서) | **예외 — 항상 열림** | `ESTOP` 발행 · 로봇 즉시 정지 |
| **⇤ 순찰 복귀** | `Shift`(체결 상태에서) | 권한·잠금 | `SET_MODE autonomy` 발행 |
| 방향 패드 W/A/S/D | `W A S D` · 방향키 | 권한·잠금 | 누르는 동안 `DRIVE`, 떼면 정지 |
| 순찰 모드 / 수동 모드 | `Space` | 권한·잠금 | 모드 전환 |
| 주행 속도 − / + | | 권한·잠금 | 0.1 m/s 단위. 상한은 설정 탭 값 |
| 카메라 각도 ▼ / ▲ | | 권한·잠금 | `CAMERA_TILT` (−45° ~ +45°) |
| 지점 이동 | | 권한·잠금 | 선택한 순찰 지점으로 `NAVIGATE` |

**Shift 는 단독 탭만 단축키로 인정한다.** `Shift+A` 같은 조합키를 누르는 순간 긴급 정지가
나가면 안 되므로, 사이에 다른 키가 없었을 때만 `keyup` 에서 실행한다.
글자를 입력하는 요소에 포커스가 있으면 무시한다.

**주행 입력은 모드를 바꾸지 않는다**(-513). 예전에는 WASD 를 누르면 수동으로 넘어갔는데,
순찰 중 화면을 잠깐 건드린 것만으로 순찰이 멈추는 셈이었다.

### 관제 — 그 외

| 조작 | 동작 |
| --- | --- |
| 전면 카메라 **더블클릭** / `Enter` | 확대 ↔ 복귀. `ESC`·닫기(✕)로도 닫힘 |

- 해제: 비밀번호 재입력. 틀려도 잠금만 유지하고 로그아웃하지 않는다
- 잠긴 채 12시간 넘기면 그때 실제 로그아웃

## 7. 지켜야 할 것

새로 그리더라도 아래는 유지해야 한다. 각 항목에는 그렇게 정한 이유가 있다.

### 7.1 안전 조작은 무엇에도 막히지 않는다

- **긴급 정지**는 권한·잠금과 무관하게 로그인만 하면 눌린다.
  코드 구조로 지킨다 — `ctlOff`(권한·잠금)와 `estopOff`(안전 예외)를 분리해 두었고,
  잠금은 `ctlOff` 에만 얹는다. **새 조건을 추가할 때도 `estopOff` 에는 넣지 말 것.**
- **화재 경보 [확인]** 도 막지 않는다. 경보를 봤다는 표시는 조작이 아니라 안전 행위다.
- 확대·잠금·모달 어느 상태에서도 위 둘은 눌려야 한다. 검증에 포함돼 있다.

### 7.2 명료성 4.5:1 — 실제로 칠해지는 색으로 잰다

유리는 뒤 배경을 끌어오므로 바탕 밝기가 흔들린다. 선언된 색만 보면 안 된다.

- **그라데이션은 `background-image` 로 들어가고 `backgroundColor` 는 투명으로 남는다.**
  `backgroundColor` 만 읽는 검사는 파란 알약 위의 흰 글자를 '흰 패널 위의 흰 글자'로
  잘못 잰다. 실제로 한 번 놓쳤다.
- 정지점을 모두 뽑아 각각 재고 **가장 나쁜 값**을 답으로 삼는다.
  구현은 `check-liquidglass.mjs` 의 `CONTRAST` 함수를 그대로 쓰면 된다.
- 색이 흐르는 배경을 강하게 할수록 대비가 내려앉는다. 색을 하나씩 밝히며 쫓지 말고,
  **글자를 담은 셀의 유리를 한 단계 조밀하게** 만드는 편이 안정적이다.

현재 값(다크 / 라이트, 최저 기준):

| 요소 | 다크 | 라이트 |
| --- | --- | --- |
| 패널 제목 | 7.90 | 10.19 |
| 상태 라벨 | 8.85 | 5.25 |
| 로그 본문 | 9.29 | 5.84 |
| 긴급 정지 | 5.03 | 5.15 |
| 순찰 복귀 | 4.96 | 6.00 |
| 순찰 모드 | 5.30 | 4.66 |
| 방향 패드 눌림 | 4.66 | 4.66 |

### 7.3 콘텐츠에는 유리를 얹지 않는다

영상·열화상·지도는 판독 대상이다. **테두리만 두르고 안은 건드리지 않는다.**
`.vwrap` 에 `backdrop-filter` 가 걸리면 검증이 실패한다.

### 7.4 색만으로 알리지 않는다

상태는 색 외에 기호·문구·형태로도 구분한다. 색각 이상에서도 읽혀야 한다.

- E-STOP: `✓ 해제` / `⚠ 체결` — 기호와 문구를 함께.
- 방향 패드 눌림: 채움 + 눌림 그림자 + 축소. 색을 못 보더라도 형태로 안다.
- 이벤트 로그: 왼쪽 색띠 + 본문 색.
- 권한 없는 버튼은 **숨기지 않고 회색으로** 남긴다. 없으면 '기능이 없는 화면'으로
  오해하지만, 회색이면 '권한이 없어 못 누른다'가 드러난다.

### 7.5 움직임을 줄여 달라는 설정을 따르되, 정보는 지우지 않는다

`prefers-reduced-motion` 에서 **애니메이션은 끄고 상태 표시는 남긴다.**
움직임을 줄이는 것과 정보를 지우는 것은 다르다.

- 화재 점멸: 깜빡임 대신 고정된 적색 표시. 주기는 **1.1초(약 0.91Hz)** —
  WCAG 2.3.1 광과민성 발작 기준(초당 3회) 아래여야 한다.
- 방향 패드: 축소만 끄고 채움·눌림 그림자는 유지.
- E-STOP 체결 깜빡임: 정지.

### 7.6 겹침 순서(z-index) 등록부

값을 바꿀 때는 이 표 전체를 함께 봐야 한다. **하나를 올리면 다른 하나가 밀린다.**

| 층 | z-index | 규칙 |
| --- | --- | --- |
| 본문 판 | 0~1 | `#pgB.sim-skin > *` 가 직계 자식을 1 로 묶는다 |
| 상단 바 | 50 | 드롭다운이 본문 뒤로 가지 않게 하는 최소값 |
| 유저 메뉴 드롭다운 | 60 | 상단 바 안쪽 |
| 카메라 확대 | 90 | 본문은 덮되 모달·경보보다 아래 |
| 열화상 PiP | 91 | 확대한 전면 영상 위 |
| 모달 | 100 | 확대·본문을 덮는다 (`createPortal` 로 `body` 에) |
| 화재 점멸 막 | 190 | 확대 중에도 보여야 한다 · `pointer-events:none` |
| 조작 잠금 띠 | 195 | |
| 경보 토스트 | 200 | |
| 화재 확인 띠 | 201 | 가장 위 — 안전 행위의 창구 |

### 7.7 로봇이 못 받는 명령을 화면이 받은 척하지 않는다

로봇 서브시스템이 죽어 있거나 프레임이 한 번도 오지 않았으면 그 패널을 흐리게 하고
'데이터 없음'을 덮는다(-462). 캔버스에는 시뮬 화면이 남아 있어서, 덮지 않으면
**목업이 실데이터로 보인다.** 열화상은 로봇이 아예 생산하지 않아 항상 여기에 해당한다.

같은 이유로 조작 패널은 `DISCONNECTED` / `로봇 오프라인` / `LIVE` 세 단계를 구분한다.
'서버에 붙었다'와 '로봇이 켜져 있다'를 한 문구로 뭉뚱그리면, 로봇이 꺼진 밤에도
`LIVE` 로 보여 조작자가 명령이 먹힌다고 오해한다.

## 8. Liquid Glass — 넣은 것과 뺀 것

애플 문서(2025-06 newsroom)의 정의를 기준으로 삼았다. **시뮬레이션 화면에만** 적용한다.

| 클래스 | 붙는 조건 | 붙이는 곳 |
| --- | --- | --- |
| `#pgB.sim-skin` | `enabled === false` (mock) | `RobotPage` |
| `#nav.sim-nav` | 관제 탭 + mock | `Nav` |
| `#pgB.cam-full` | 전면 카메라 확대 중 | `RobotPage` |

실서버 관제 화면은 건드리지 않았다 — 운영 중인 화면을 시연용 개편과 한 번에 바꾸지 않는다.

### 넣은 것

**주변색 적응** — *"색상은 주변 콘텐츠에 따라 달라지며"*
흰 틴트를 얇게(4.5%) 유지하고 채도를 **2.3배**로 끌어올려, 유리가 스스로 색을 갖지 않고
뒤에 깔린 색을 빌려 쓰게 한다. 흰 반투명을 두껍게 덧칠하면 무엇을 깔든 흰 유리가 된다.

**동심원 모서리** — *"모서리는 동심원 형태로 거듭나"*

```css
#pgB.sim-skin{
  --r: 26px;     /* 바깥 유리판 반지름 */
  --pad: 14px;   /* 유리판 안쪽 여백 */
  --r-in: 12px;  /* = var(--r) - var(--pad) */
  --blur: 30px;
  --sat: 1.9;
}
```

**굴절시킬 색장** — 균일한 배경은 아무리 정교하게 굴절시켜도 결과가 같아 유리로 보이지 않는다.
5겹 색장을 깔되 **밝기는 눌러 둔다** — 영상과 열화상이 주인공이다.

### 뺀 것 — 굴절 링

테두리에만 별도의 `backdrop-filter` 를 걸어 유리 두께를 만드는 방식을 구현했다가 걷어냈다.

**원리는 맞지만 화면에서 판 위쪽에 밝은 가로 막대가 생긴다.** 링이 배경을 판 본체와 다른
세기로 샘플링하는데, 배경에 밝기 변화가 있는 곳에서는 그 차이가 곧 띠로 드러난다.

| 시도 | 결과 |
| --- | --- |
| 링 폭 10 → 7 → 4px | 옅어질 뿐 사라지지 않음 |
| 밝기 보정 제거 | 남음 |
| 흐림 비율 0.12 → 0.7 → 0.85 | 남음 |
| 밝기 대신 대비만 다르게 | 남음 |

**균일한 배경에서만 깨끗한 효과다.** 다시 시도할 생각이라면 배경을 균일하게 만들 각오부터 해야 한다.

### 뺀 것 — 포인터 추적 스펙큘러

포인터 좌표를 CSS 변수 하나로 넘기고 그 변수를 **판마다** 읽게 했더니, 판 수만큼 광원이
생겨 **커서를 따라다니는 원이 다섯 개**가 됐다. 반사광은 하나여야 한다.

### 뺀 것 — 판 위의 인공적인 선

- 위쪽 좌우 16px 들여쓴 1px 흰 선 → 제목 위 **흰 가로 막대**로 보였다.
- 제목 아래 `border-bottom` → 유리판에 그은 **회색 줄**.
- 판 배경의 대각 그라데이션 → 위쪽이 밝아져 **띠**.

셋 다 없앴다. 검증은 이제 그 **부재**를 확인한다 — 다시 들어오면 잡힌다.

## 9. 겪은 함정

**이 절이 이 문서의 핵심이다.** 전부 실제로 당한 것이고, 새로 그려도 그대로 재발한다.

### `backdrop-filter` 는 부작용이 둘이다

1. **쌓임 맥락을 만든다.** 안쪽 요소의 `z-index` 가 그 안에 갇힌다.
2. **`position:fixed` 자손의 포함 블록이 된다.** `inset:0` 이 화면이 아니라 그 상자 기준이 된다.

둘 다 실제로 터졌다. 상단 바에 유리를 입히자 —
- 유저 메뉴 드롭다운이 대시보드 뒤로 숨었다(**버튼이 안 눌리는 것처럼 보였다**).
- 마이페이지 모달이 56px 짜리 바 안에 갇혔다.

**대응**: 상단 바에 명시적 `z-index` 를 주고, `Modal` 은 `createPortal` 로 `body` 에 그린다.
조상에 `backdrop-filter`·`transform`·`filter` 가 있으면 어디서든 같은 문제가 생기므로,
사례를 막는 대신 원인을 없앴다.

### `:is()` 는 인자 중 가장 특정한 것의 특정도를 가져간다

```css
:root[data-theme] #pgB.sim-skin :is(… .dpad button … .dbtn:not(.stop):not(.go)) { … }
```

`.dbtn:not(.stop):not(.go)` 때문에 **(1,5,1)** 이 된다. 뒤에 오는 눌림 규칙(0,4,2)이
아무리 나중에 와도 이기지 못한다 — 라이트 모드에서 방향 패드 눌림이 안 보였다.

**대응**: 특정도를 더 올려 맞서지 말고, 그 목록에서 해당 요소를 **빼라.**
겨루는 자리를 없애는 편이 나중에 또 밀리지 않는다.

### `#pgB.sim-skin > *{z-index:1}` 이 자손을 묶는다

직계 자식(`.b-grid`)이 쌓임 맥락을 만들어, 그 안의 `z-index:90` 이 바깥의 `89` 를 이기지 못한다.
카메라를 확대해도 화면이 어두운 막에 덮였다. **큰 값을 줬는데 안 먹으면 조상을 의심하라.**

### 그림자가 간격보다 넓으면 틈이 회색이 된다

판 간격 16px 에 44~50px 블러 그림자를 드리우니 이웃한 그림자끼리 겹쳐 틈을 메웠다.
배경 색장이 안 보이고 회색만 돌았다. **색장 위에 놓인 유리는 큰 그림자가 필요 없다** —
떠 있다는 느낌은 테두리가 이미 만든다. 현재 4px/12px.

### 어두운 막은 배경을 죽인다

확대 시 뒤에 막을 깔았더니 애써 만든 배경이 사라지고 화면이 한 겹 어두워졌다.
**막 없이 배경을 그대로 두고 그 위에 영상만 크게** 띄우는 편이 자연스럽다.
가려야 할 것은 다른 판들뿐이고, 그건 `visibility:hidden` 으로 충분하다.

### 상단 바를 반쯤 덮으면 어중간하다

가린 것도 아니고 보인 것도 아닌 모양이 된다. 확대 창을 **바 아래에서 시작**하게 하면
탭·시계·계정 메뉴를 확대 중에도 쓸 수 있고 배경도 사방에서 균일하게 보인다.

### 작은 창에 큰 머리말을 그대로 얹지 마라

열화상 PiP 에 패널 헤더를 그대로 뒀더니 **영상보다 껍데기가 커** 보였다.
화면 속 화면은 **영상 자체가 창**이다 — 여백을 없애고 이름표를 영상 위 칩으로 올린다.

### `fieldset[disabled]` 은 자손의 `disabled` 프로퍼티를 바꾸지 않는다

실제 상태는 `:disabled` 가 안다. 조작 요소가 많은 화면(설정·운영)을 통째로 잠글 때는
`fieldset` 이 편하지만, **검사는 `.matches(':disabled')` 로 해야 한다.**

### `.js` 의 JSDoc 타입은 `.ts` 에서 무시된다

확장자 전환(-571) 때 드러났다. 타입 주석을 남겨 두어도 검사되지 않으므로,
`.ts` 로 옮길 때는 실제 타입으로 바꿔야 한다.

| `/topic/video/{robotId}` | `FRONT` · `THERMAL` 프레임 |
| `/topic/mapping` | 맵 모델링 완료 · 도면 준비 완료 |

발행 명령: `ESTOP` · `DRIVE` · `SET_MODE` · `NAVIGATE` · `CAMERA_TILT` ·
`START_MAPPING` · `STOP_MAPPING` · `SAVE_MAP`

JWT 를 CONNECT 헤더와 REST 헤더 양쪽에 싣는다. 없으면 실시간 연결이 거부된다.

### 세션 정책 (`sessionPolicy.ts`)

| 상수 | 기본값 | env |
| --- | --- | --- |
| 유휴 → 조작 잠금 | 60분 | `VITE_SESSION_IDLE_MIN` |
| 잠금 상한 → 로그아웃 | 12시간 | `VITE_SESSION_LOCK_MAX_MIN` |
| 선제 토큰 갱신 | 만료 5분 전 (수명의 절반 이하로 잘림) | |
| STOMP 인증 실패 유예 | 20초 | `VITE_STOMP_AUTH_GRACE_SEC` |
| 판정 주기 | 5초 | |

**활동으로 인정되는 것**: 사용자 조작(마우스·키보드·터치·스크롤) + **이벤트 로그 신규 기록**.
텔레메트리·영상·맵 갱신은 활동이 아니다 — 로봇 전원만 켜져 있으면 끊임없이 흐르므로
활동으로 치면 유휴 판정이 영원히 성립하지 않는다.

### 로봇 상한 (`config.ts`)

```
ROBOT_V_MAX = 1.0 m/s     ROBOT_W_MAX = 0.6 rad/s
```

관제가 보내는 `DRIVE` 는 로봇의 `teleop_node` 에서 잘린다. 이 값보다 큰 수를 보내면
로봇이 조용히 클램프해 **슬라이더 표시와 실제 속도가 어긋난다.**
선속도와 각속도의 상한이 서로 다르므로 하나의 배율을 양쪽에 곱하면 안 된다 —
회전만 먼저 상한에 걸린다.

### 설정 기본값

```
vMax 1.0 m/s · wMax 0.6 rad/s · tempWarn 52℃ · tempCritical 60℃
순찰 지점 3개 (분전반 A/B/C)
```

## 11. 검증

**선언된 스타일이 아니라 렌더된 결과를 재야 한다.** 이 원칙을 어겨 두 번 놓쳤다.

- 유저 메뉴 버그: `!!document.querySelector('.usermenu-drop')` 로 존재만 확인하면 **통과한다.**
  메뉴는 실제로 열려 있었고, 대시보드 뒤에 숨어 있었을 뿐이다.
  → `elementFromPoint` 로 **그 자리에 무엇이 잡히는지** 본다.
- 방향 패드 버그: CSS 규칙 자체는 올바로 작성돼 있었고 `:is()` 특정도에 밀렸을 뿐이다.
  → **실제로 키 입력을 보내고**(`Input.dispatchKeyEvent`) 렌더된 값을 잰다.

### 검증 스크립트

`tools/verify/` 에 있다. 헤드리스 Chrome + CDP + 가짜 백엔드 조합.
사용법은 [`tools/verify/README.md`](../tools/verify/README.md).

```sh
node tools/verify/serve-fake-backend.mjs   # 가짜 백엔드
node tools/verify/run-all.mjs              # 화면 검증 전부
```

| 스크립트 | 무엇을 보는가 |
| --- | --- |
| `check-liquidglass` | 프레임워크 미사용 · 인공 선의 부재 · 주변색 적응 · 동심원 모서리 · 콘텐츠 비유리화 · 두 테마 명료성 · 커서 추종 부재 · 실서버 격리 |

## 12. 되돌아오는 법

**이 문서만으로는 되돌아올 수 없다.** 문서는 *왜 그렇게 했는지*를 남길 뿐,
*무엇이 어떤 코드였는지*와 *돌아왔는지 어떻게 아는지*는 담지 못한다.
그 둘을 아래로 갖춘다.

### 세 가지가 모두 있어야 한다

| | 무엇 | 어디에 |
| --- | --- | --- |
| **왜** | 결정과 실패의 기록 | 이 문서 |
| **무엇** | 그 시점의 코드 | git 태그 `design/liquid-glass-2026-08` |
| **확인** | 돌아왔는지 재는 수단 | `tools/verify/` |

셋 중 하나라도 빠지면 되돌아올 수 없다. 특히 **검증 수단**이 없으면 코드를 되돌려도
그것이 정말 예전 상태인지 알 방법이 없다 — 화면은 눈으로 봐서 같아 보여도
명료성 4.5:1 이나 안전 조작 예외는 눈에 보이지 않는다.

### 새로 그리기 전에

```sh
# 1) 기준선을 잡는다. 지금이 통과하는지 확인하고 시작해야
#    무엇을 깨뜨렸는지 알 수 있다.
node tools/verify/run-all.mjs

# 2) 돌아올 지점을 남긴다.
git tag design/liquid-glass-2026-08
git push origin design/liquid-glass-2026-08
```

### 되돌리기

```sh
# 전부 되돌린다
git checkout design/liquid-glass-2026-08 -- FE/bbiyong-react/src

# 화면 스타일만 되돌린다
git checkout design/liquid-glass-2026-08 -- FE/bbiyong-react/src/styles/app.css

# 확인 — 반드시 돌린다
node tools/verify/run-all.mjs
```

### 일부만 가져올 때

새 디자인을 유지하면서 특정 결정만 되살리고 싶다면, [7절](#7-지켜야-할-것)의 항목별로
해당 검증이 통과하는지 보면 된다. 각 검사는 **하나의 결정에 대응**하도록 썼다.

| 되살리려는 것 | 확인할 검사 |
| --- | --- |
| 안전 조작 예외 | `check-653` [3] · `check-camfull` [4] |
| 명료성 4.5:1 | `check-liquidglass` [6] · `check-dpad` |
| 겹침 순서 | `check-usermenu` [3] · `check-camfull` [4] |
| 콘텐츠 비유리화 | `check-liquidglass` [5] |
| 저감 모션 | `check-643` [9] · `check-dpad` |

## 13. 다음 개편에게

0. **[12절 되돌아오는 법](#12-되돌아오는-법)대로 기준선을 잡고 태그를 남겨라.**
   이것을 건너뛰면 나머지 조언이 소용없다 — 되돌릴 곳이 없다.
1. **[7절 지켜야 할 것](#7-지켜야-할-것)을 먼저 읽어라.** 특히 안전 조작(7.1)과 겹침 순서(7.6).
2. **[9절 겪은 함정](#9-겪은-함정)은 화면을 새로 그려도 그대로 재발한다.**
   `backdrop-filter` 를 쓰는 순간 쌓임 맥락과 포함 블록 문제가 따라온다.
3. `node tools/verify/run-all.mjs` 로 **현재가 통과하는지** 확인하고 시작하라.
4. 제거한 기능(굴절 링 · 포인터 추적 · 판 위의 선)은 검증이 **'없는가'** 를 확인한다.
   다시 넣을 생각이라면 그 검사부터 고쳐야 하고, 그때 8절의 실패 기록을 다시 읽어라.
5. 실서버 화면을 함께 바꿀 생각이라면 **범위를 먼저 합의하라.** 지금은 시뮬 전용이고,
   그 격리가 검증으로 지켜지고 있다.
6. **로봇에게 나가는 것은 되돌릴 수 없다.** 조작 관련 화면을 손볼 때는 가짜 백엔드로
   확인하고, 실서버 주소로 요청이 나가지 않는지 먼저 확인하라.
