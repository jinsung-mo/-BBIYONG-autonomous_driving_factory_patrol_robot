# `ref/` — 참조 전용 코드

**빌드 대상이 아니다. 읽으라고 둔 코드다.**

이 디렉터리에는 다른 파트가 이미 만들어 **실물 로봇에서 돌려본** 구현이 들어온다.
같은 기능을 새로 만드는 사람이 "그래서 실제로 어떻게 했는데?"를 볼 곳이다.

---

## 규칙 — 네 줄

1. **어떤 빌드도 이 디렉터리를 읽지 않는다.** 번들러·`tsconfig`·CI 어디에도 넣지 마라.
2. **`import` 하지 마라.** 읽고, 이해하고, 여러분 코드로 **다시 써라**.
   여기 코드는 여러분 스택(React·TS)이 아니고, 여러분 백엔드 계약(STOMP)도 안 쓴다.
3. **여기 파일을 고치지 마라.** 원본이 따로 있다(각 하위 README 참조). 여기서 고치면 원본과 어긋나기만 한다.
4. **`FE/` 를 침범하지 않는다.** 이 디렉터리는 `FE/` 밖에 있고, 앞으로도 그래야 한다.
   FE 산출물에 참조 코드가 섞여 들어가는 것을 막으려고 일부러 저장소 루트에 뒀다.

## 🔑 FE 파트에게 — 이 폴더를 읽어 주세요

### 어떻게 도달하는가

`ref/` 는 **`main` 바로 밑에 놓인다.** 어느 파트 폴더에도 속하지 않으므로(`FE/` 변경 0건)
파트 브랜치를 거치지 않고 `main` 으로 직접 들어간다. 머지 뒤에는 `main` → `fe/main` → `fe/dev`
한 갈래만 타고 내려오면 여러분 브랜치에서 보인다.

**머지 전에도 브랜치를 직접 읽으면 된다** — 체크아웃도, 브랜치 전환도 필요 없다.

```bash
git fetch origin

# 이 README
git show origin/docs/S15P11E101-372-ref-for-fe-to-main:ref/README.md

# 본론 — 대시보드 참조본 README
git show origin/docs/S15P11E101-372-ref-for-fe-to-main:ref/orin-dashboard/README.md

# 실제 코드
git show origin/docs/S15P11E101-372-ref-for-fe-to-main:ref/orin-dashboard/static/index.html
git show origin/docs/S15P11E101-372-ref-for-fe-to-main:ref/orin-dashboard/server.py
git show origin/docs/S15P11E101-372-ref-for-fe-to-main:ref/orin-dashboard/nav_protocol.py
```

머지된 뒤에는 브랜치명 자리에 `main` 을 넣으면 된다 — `git show origin/main:ref/README.md`.

파일을 손에 놓고 보고 싶으면 **작업 트리를 건드리지 말고** 별도 디렉터리로 빼라 —

```bash
git worktree add ../S15P11E101-ref origin/docs/S15P11E101-372-ref-for-fe-to-main
# 다 보고 나면
git worktree remove ../S15P11E101-ref
```

GitLab 웹에서 볼 수도 있다 — 저장소 → 상단 브랜치 선택기에서
`docs/S15P11E101-372-ref-for-fe-to-main` 를 고르고 루트의 `ref/` 로 들어가면 된다.
(이 MR 의 **Changes** 탭에서도 전체 파일이 그대로 보인다.)

|---|---|---|

| 4 | 〃 **§5 함정** | 🔴 **여기가 이 폴더의 값어치다.** 실물에서 틀려 보고 고친 것 10건 — 좌표 변환, 신선도(stale) 처리, 폴링 페이싱, 데드맨 규약 |

**§5 만 읽어도 본전은 뽑는다.** 나머지는 필요할 때 되돌아오면 된다.

질문은 로봇 파트로. 코드가 왜 그렇게 생겼는지는 대부분 §5 에 이유가 적혀 있다.

## 왜 그대로 쓰면 안 되는가

이 코드는 **로봇에 직접 붙는 개발·시연용 도구**다. 제품 프런트엔드가 아니다.
전제가 다르다 —

| | `ref/` 의 코드 | 팀 FE 가 실제로 놓인 환경 |
|---|---|---|
| 데이터 출처 | Orin 의 `server.py` 에 **직결** | Spring 백엔드 경유 (**STOMP**/REST) |
| 인증 | **없음.** nginx Basic Auth 에 전부 위임 | 사용자 인증·토큰이 있다 |
| 사용자 | 개발자 1명 | 다수. 누가 조종했는지 남아야 한다 |
| 프레임워크 | 없음 (의존성 0, 단일 파일) | React |

**그래서 베낄 것은 코드가 아니라 "판단"이다.**
좌표 변환식, 신선도(stale) 처리, 폴링 페이싱, 데드맨 규약 — 이건 실물에서 틀려 보고 고친 것들이라 그대로 값어치가 있다.
DOM 조작·`innerHTML`·전역 상태는 **베끼지 마라.** 특히 `innerHTML` 은 이스케이프가 없어 그대로 옮기면 XSS 가 따라온다(하위 README 의 "보안" 절).
